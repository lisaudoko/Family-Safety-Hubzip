# Current State

## Status

Feature-complete MVP+ in active development. Mobile app (Expo) + Express API + PostgreSQL all functional. Not yet published to app stores.

## Completed Major Systems

- **Auth**: parent register/login (bcrypt + UUID Bearer sessions, 90-day TTL at issuance, enforced at request time by `requireAuth` since 2026-07-10), child PIN login via family code, forgot/reset password, offline `local_` accounts with background server sync. **Email verification** (implemented 2026-07-11, product owner decision 2026-07-10): registration now issues a hashed 6-digit code (`email_verification_codes`, 15-min TTL, same shape as password-reset codes) and emails it via the existing email mechanism (`sendEmailVerificationEmail` in `src/lib/email.ts`, nodemailer if `SMTP_HOST` is set, else logged — mirrors `sendPasswordResetEmail`). `POST /api/auth/verify-email` (`{ code }`) marks `profiles.email_verified = true` and invalidates the code; `POST /api/auth/resend-verification` reissues one, rate-limited 5/hr per user (mirrors `notifications.ts`'s digest limiter). Both audited via `logAuditEvent` (`email_verification_requested`/`email_verification_completed`). **Verification is informational only — no endpoint or feature is gated on `email_verified` today**; this was an explicit product-owner-silent default (lowest-risk choice), flagged as an open question for future tightening. Mobile: `emailVerified` surfaced on `ApiUser`/`AuthContext.User`, a banner + "Enter code"/"Resend code" modal on the parent Profile tab (`app/(tabs)/profile.tsx`) when unverified; local-only offline accounts default to `emailVerified: true` (no server concept to gate on).
- **Education**: 9 courses, 64 lessons, 13 quizzes, 22 badges, weekly tips (snapshot of mobile `data/seed.ts` as of 2026-07-08; DB counts may differ). Content lives in DB (`courses`/`lessons`/`quizzes`/`quiz_questions`/`badges`/`weekly_tips` tables) served via `/api/curriculum`; mobile also has static seed in `data/seed.ts`. Parent-facing progress: `GET /api/dashboard/children/:childId/progress` (added 2026-07-11) surfaces a child's `user_progress` (course completion %, earned badges, assessment score) to their parent, family-scoped; `apiGetChildProgress()`/`useChildProgress` exist on mobile but aren't wired into a screen yet.
- **Assessment**: 10-question Social Media Readiness Assessment with per-category scoring (client-side, seed data).
- **Family**: family CRUD, children profiles (age bands), family technology agreement builder, family code for child login. Child accounts now get a role-aware Family tab: `GET /api/family` returns a self-excluded `siblings` list alongside `parents`/`children`, and `GET/PUT /api/family/agreement` are family-scoped via session `familyId` (children can read, only parents can write) — see 2026-07-10 entry in `AI_CHANGELOG.md`.
- **Challenges**: 8 family challenges with step tracking.
- **Devices**: device registration, heartbeat sync, screen-time/activity/education-activity event reporting, parent analytics (`screen-time`/`activity`/`education`/`summary`) + dashboard endpoints. Ownership validation (owner-or-family-parent gating on GET/PATCH/DELETE, owner-only on heartbeat/events) and a platform-neutral capability model (`lib/capabilities.ts`) were already implemented; verified and regression-tested 2026-07-10 (previously understated in `NEXT_TASK.md`). Education activity (lesson/quiz/challenge/assessment completions) now has its own `education_activity` event type/`lesson_participation` capability, distinct from general app `activity` events — see `AI_CHANGELOG.md`.

## Current Risks

- `replit.md` describes an older, smaller version of the system (6 tables, "no Stripe") — trust `AI_CONTEXT/` docs and the code, not `replit.md`, for feature inventory.
- Duplicate content sources: curriculum exists in both DB tables and `artifacts/mobile/data/seed.ts`; drift is possible.
- **Security gaps**: (Fixed 2026-07-10: `PUT /family/agreement` IDOR, child CRUD ownership checks, session `expires_at` enforcement in `requireAuth`, `DELETE /devices/:deviceId` RBAC (child could de-register any family device — now `requireParent`); full cross-cutting family-data-isolation audit across devices/dashboard/analytics/family/coach/billing/curriculum/notifications found no further gaps; audit logging and the admin role are now implemented — see `AI_CHANGELOG.md`.) See `docs/SECURITY.md` "Known Gaps" for what remains (CORS). Email verification flow implemented 2026-07-11 (informational only, not access-gated).
- **API server will not boot without `STRIPE_SECRET_KEY`**: `src/lib/stripe.ts` throws at import time if the env var is missing, crashing the whole server (not just billing routes). Set the secret or refactor to lazy-init if this becomes a problem.
